# 玩家鸡蛋/西红柿互动功能设计

日期：2026-08-14

## 1. 背景与目标

在房间主界面中，玩家 A 点击玩家 B 的头像后，可以选择向 B 扔鸡蛋或西红柿。房间中的在线客户端同步看到一个有体积感的道具模型从 A 的头像飞向 B 的头像，并在命中时播放炸开、飞溅效果。

该功能是纯娱乐互动，不改变房间、牌局、下注、开牌或计分状态。庄家在 `opening` 阶段仍需选择开牌对象，因此头像互动与玩家卡片选择必须使用互不冲突的点击热区。

## 2. 已确认需求

- 可选道具为鸡蛋和西红柿。
- 点击其他玩家头像打开道具菜单。
- 互动仅在房间主界面的 `waiting`、`betting` 和 `opening` 阶段可用。
- `opened` 结果页不提供互动入口，也不播放新收到的互动动画。
- 房间内在线客户端只显示飞行动画和命中效果，不显示“A 向 B 扔了……”文字。
- 庄家在 `opening` 阶段：
  - 点击头像只打开道具菜单；
  - 点击玩家卡片的非头像区域选择或取消开牌。
- 每位玩家每秒最多成功发送一次道具，由服务端限流。
- 玩家不能向自己扔道具。
- 可以向仍在房间内的离线玩家扔道具；其他在线客户端能看到，离线玩家重新连接后不补播。
- 视觉方向为高饱和、半 3D 卡通模型：飞行时有体积、材质高光和拖影，命中时有蛋壳/蛋液或番茄汁炸开效果。

## 3. 非目标

本次不包含：

- 结果页互动；
- 道具库存、金币或付费系统；
- 聊天记录或互动历史；
- 命中计数、排行榜或成就；
- 音效和震动；
- 互动事件持久化；
- 对现有玩家身份体系进行全面鉴权重构；
- 将互动同步到原微信小程序项目。

## 4. 技术方案

采用独立 Socket.IO 瞬时事件，不把互动写入房间对象，也不复用 `roomUpdate`。

### 4.1 客户端发送

玩家选中道具后发送：

```js
socket.emit('throwProp', {
  roomId,
  targetPlayerId,
  propType: 'egg' // 或 'tomato'
}, callback)
```

Payload 不包含 `senderPlayerId`。发送者身份由服务端根据当前 Socket 关联的玩家确定，防止客户端在事件参数中直接伪造发送者。

### 4.2 Socket 身份关联

现有 `joinRoom(roomId, playerId)` 流程继续负责加入 `room:<roomId>` Socket 频道，并沿用连接闭包中的 `socketPlayerId`、`socketRoomId` 记录身份。只有当该 `playerId` 已存在于 HTTP 房间玩家列表时，服务端才设置这两个身份变量并更新 `playerSocketMap`。

邀请页尚未通过 HTTP `joinRoom` 入桌时，仍可订阅房间频道以保持现有邀请流程，但不会获得可发送互动的 Socket 身份。`joinRoomFromInvite()` 成功入桌后，客户端必须再次调用 `joinSocketRoom(roomId)`，使服务端在玩家已存在的情况下登记身份。

服务端处理互动时还要同时确认：

- `playerSocketMap.get(senderPlayerId) === socket.id`，使旧连接不能继续代表该玩家发送；
- `socket.rooms.has('room:' + roomId)`，使已经执行 `leaveRoom` 的连接不能继续发送。


### 4.3 服务端验证

`throwProp` 按以下顺序验证：

1. Socket 已关联玩家和房间；
2. 房间存在；
3. 发送者仍在房间玩家列表中；
4. 目标仍在房间玩家列表中；
5. 目标不是发送者本人；
6. `propType` 严格为 `egg` 或 `tomato`；
7. 当前 Socket 是发送者最新登记的连接；
8. 当前 Socket 仍在目标房间频道中；
9. 当前连接距离上次成功发送至少 1000ms。

限流时间记录在 `socket.data.lastPropAt`。只有通过全部验证并准备广播时才更新时间，失败操作不消耗冷却时间。玩家重连后冷却状态重置是可接受行为。

### 4.4 服务端广播

验证成功后广播：

```js
io.to(`room:${roomId}`).emit('propThrown', {
  roomId,
  senderPlayerId,
  targetPlayerId,
  propType
})
```

互动不修改 `room`，不调用 `broadcastRoom()`，也不触发 `roomUpdate`。

发送客户端不进行乐观动画，而是与其他客户端一样等待 `propThrown`，确保被拒绝或限流的操作不会只在本地播放，也避免发送者重复播放。

## 5. 客户端交互设计

### 5.1 头像与卡片热区

其他玩家卡片保留为庄家开牌选择热区，但头像包装层成为独立互动热区。

- 头像点击处理必须调用 `event.stopPropagation()`。
- 头像点击只打开道具菜单，不调用 `togglePlayer()`。
- 踢人按钮继续调用 `event.stopPropagation()`，只执行踢人。
- 玩家名字、状态、酒杯数等非头像区域在庄家 `opening` 阶段继续调用 `togglePlayer()`。
- 互动菜单和动画不能修改 `state.selectedPlayers` 或 `state.selectedCount`。
- 卡片已有的开牌选中视觉保持不变。

所有房间主界面头像元素增加稳定定位属性，例如：

```html
<div class="avatar-wrap" data-player-id="...">...</div>
```

当前玩家和其他玩家的头像都必须带有玩家 ID，以便任意客户端定位动画起点与终点。

### 5.2 道具菜单

点击其他玩家头像后，在头像附近显示紧凑菜单：

```text
[鸡蛋模型图标] [西红柿模型图标]
```

行为规则：

- 每个按钮的有效点击区域至少为 48×48 CSS 像素；
- 菜单使用 `position: fixed`，依据头像坐标定位；
- 根据视口剩余空间自动选择向上或向下展开；
- 菜单不能超出左右视口安全边距；
- 点击道具后立即关闭菜单并发送事件；
- 点击菜单外、再次点击同一头像或点击另一头像时关闭/切换菜单；
- 房间重新渲染、状态进入 `opened`、退出房间或切换路由时关闭菜单；
- 菜单层级高于玩家卡片和底部操作栏，低于确认弹窗、认证弹窗和全局 Loading；
- 菜单不遮挡庄家的底部开牌按钮。

## 6. 视觉资产

### 6.1 美术方向

采用已确认的半 3D 卡通风格：

- 高饱和色彩，适配绿色牌桌和酒桌游戏氛围；
- 模型具有清晰轮廓、体积阴影和高光；
- 鸡蛋使用暖白蛋壳与金黄色蛋黄；
- 西红柿使用鲜红果肉、绿色蒂和高光表皮；
- 飞溅效果热闹但范围紧凑，不持续遮挡头像、名字和牌局操作；
- 不使用纯 Emoji 作为最终飞行模型。

### 6.2 资产拆分

建议输出透明背景 WebP：

```text
public/assets/props/
├── egg-projectile.webp
├── egg-impact.webp
├── egg-splat.webp
├── tomato-projectile.webp
├── tomato-impact.webp
└── tomato-splat.webp
```

用途：

- `*-projectile.webp`：飞行过程中持续显示的完整模型；
- `*-impact.webp`：命中瞬间的主体炸开效果；
- `*-splat.webp`：命中后短暂保留并淡出的飞溅残影。

飞行模型与命中效果必须是独立透明资产，以便分别控制轨迹、旋转、缩放和消失时间。资产边缘留出飞溅安全空间，避免动画缩放时被图片边界裁切。

## 7. 动效规范

### 7.1 时间线

```text
菜单选择
  → 模型蓄力缩放：80ms
  → 弧线飞行：520–650ms
  → 命中炸开：180–240ms
  → 飞溅残影淡出：350–500ms
```

完整互动约 1 秒结束。

### 7.2 飞行模型

- 移动端视觉尺寸约 40–48px；
- 起点和终点分别为发送者与目标头像中心；
- 使用 Web Animations API 或等价方式创建包含起点、中间控制点和终点的关键帧；
- 中间控制点向上偏移，形成轻微抛物线；
- 飞行过程中旋转 180–360 度，并带轻微缩放；
- 可增加同色低透明度拖影，但拖影不能明显扩大点击区域或遮挡文字；
- 动画元素挂载到 `document.body`，使用 `position: fixed` 和 `pointer-events: none`。

### 7.3 命中效果

- 命中飞溅视觉尺寸约 72–88px；
- 飞溅中心对准目标头像中心；
- 先播放 `impact` 快速放大，再切换或叠加 `splat` 淡出；
- 鸡蛋命中显示碎蛋壳、蛋白和蛋黄飞溅；
- 西红柿命中显示果皮碎片、果肉和番茄汁飞溅；
- 命中时目标头像可进行一次约 180ms 的轻微压缩和左右晃动；
- 飞溅不得永久改变头像 DOM 或玩家数据；
- 动画结束后清理所有临时元素和临时 class。

### 7.4 层级与并发

- 动效层高于玩家卡片；
- 动效层低于邀请、踢人、认证和 Loading 弹层；
- 动效元素不响应指针事件，因此不影响开牌、下注或踢人；
- 不建立全局队列，不同发送者的动画可以并行；
- 同一发送者由服务端一秒冷却限制动画密度。

### 7.5 减少动态效果

当 `prefers-reduced-motion: reduce` 生效时：

- 省略完整弧线飞行；
- 在目标头像位置显示低位移、短时长的命中效果；
- 不执行头像晃动；
- 仍保持鸡蛋和西红柿视觉可区分。

## 8. 页面与状态边界

客户端仅在以下条件全部满足时播放：

- 当前路由是房间主界面；
- 当前房间 ID 与事件 `roomId` 一致；
- 当前房间状态不是 `opened`；
- 起点和终点头像元素都存在于 DOM。

任一条件不满足则静默忽略。Socket 事件不重放，因此重新连接或返回房间时不会补播旧互动。

进入结果页、退出房间或发生完整房间重绘时，应关闭道具菜单；已存在的飞行动画在离开房间主界面时立即清理。

## 9. 错误处理

服务端 callback 使用稳定错误码：

- `ROOM_NOT_FOUND`
- `SENDER_NOT_IN_ROOM`
- `TARGET_NOT_FOUND`
- `CANNOT_TARGET_SELF`
- `INVALID_PROP`
- `STALE_SOCKET`
- `RATE_LIMITED`

处理规则：

- `RATE_LIMITED` 静默忽略，不产生 Toast；
- 目标离开、页面切换或头像暂时不存在时静默忽略；
- Socket 未连接或发送超时，可以复用现有轻提示告知连接暂不可用；
- 服务端异常不得触发本地动画；
- 无论成功或失败，都不能改变游戏状态和庄家的开牌选择。

## 10. 测试设计

### 10.1 Socket 与服务端行为

在现有浏览器测试运行器的 Socket.IO 测试组中覆盖：

1. 合法鸡蛋事件广播正确的房间、发送者、目标和类型；
2. 合法西红柿事件正常广播；
3. 向自己扔返回 `CANNOT_TARGET_SELF`；
4. 不存在或已离开的目标返回 `TARGET_NOT_FOUND`；
5. 非法道具类型返回 `INVALID_PROP`；
6. 非房间成员不能发送；
7. 旧 Socket 不能代表玩家发送；
8. 一秒内第二次成功请求返回 `RATE_LIMITED`；
9. 冷却结束后可以再次发送；
10. 被拒绝的请求不消耗冷却时间；
11. 互动不修改房间状态、下注、手牌、分数或轮次结果；
12. 互动不触发额外 `roomUpdate`。

### 10.2 前端交互

验证：

1. `waiting`、`betting`、`opening` 阶段可以点击其他玩家头像；
2. `opened` 结果页没有互动入口；
3. 点击头像只打开菜单；
4. 点击菜单外关闭菜单；
5. 点击鸡蛋或西红柿后菜单立即关闭；
6. 庄家在 `opening` 阶段点击头像不会切换开牌选择；
7. 庄家点击卡片非头像区域仍可选择和取消开牌；
8. 已选择玩家后发送道具，选中状态保持不变；
9. 踢人按钮既不打开菜单，也不切换开牌选择；
10. 飞行动画起终点对应正确玩家头像；
11. 鸡蛋与西红柿播放各自的模型和命中效果；
12. 多个玩家并发互动时动画可重叠且不阻塞操作；
13. 进入结果页或离开房间时清理菜单和动画；
14. 窄屏下菜单不超出视口；
15. `prefers-reduced-motion` 下使用简化命中效果。

## 12. 验收标准

功能完成需同时满足：

- 两名或更多玩家在房间主界面时，可以通过头像菜单选择鸡蛋或西红柿；
- 所有在线房间客户端看到一致的模型飞行和命中炸开效果；
- 服务端拒绝非法目标、非法道具、自我目标、旧连接和一秒内重复发送；
- 庄家 `opening` 阶段的头像互动与卡片开牌选择完全分离；
- 互动不触发房间状态更新，不影响任何牌局数据；
- 结果页不提供或播放互动；
- 动画不会拦截点击、长期遮挡核心内容或留下未清理 DOM；
- 新增自动测试通过，并完成手机窄屏与庄家开牌阶段的人工验证。
